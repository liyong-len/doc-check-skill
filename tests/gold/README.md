# 金标评估

模型输出有不确定性，不进 CI。改用金标评估来判断规则与提示词是否需要调整。

## 当前金标

`gold_set.json` 里现在只有 **4 条**，全部来自 `tests/make_samples.py` 生成的样本文档
`sample_company.docx`。这是一个**起点，不是基准**：4 条样本上的数字只能说明「有没有明显缺口」，
不能用来比较两个版本的优劣。扩充金标时请按下面的做法加，加完记得把上面的条数改掉。

金标只收**语义层的九类**（错别字用词、标点格式、前后矛盾、主体名误用、引用张冠李戴、
待补充内容、数字逻辑、表述不清、术语一致性）。阶段①的确定性类别（字体一致性、段落格式一致性、
标题层级体例、图表题注体例、表格体例、列表与编号、引用标记、数字与单位、主体名称、主体串写、
术语与缩写）由单元测试覆盖，不进金标——`SKILL.md` 明确禁止模型写这些类别，
混进来会把「模型本来就不该报」永远算成漏报。

## 做法

1. 准备一批带已知问题的文档（可用 `tests/make_samples.py` 生成的样本，也可另备真实文档）。
2. 人工标注所有已知问题，填入 `gold_set.json`。每条包含 `file`、`category`、`quote`、`severity`。
   `quote` 必须是原文片段，且要真实存在于被检查的文档里。
3. 跑一次完整检查（阶段①、阶段②、阶段③），得到 `findings.json`。
4. 执行：

```bash
python scripts/evaluate.py --gold tests/gold/gold_set.json --predicted .doc-check-work/findings.json
```

5. 记录召回率与精确率。漏报多的类别优先补规则或提示词，误报多的类别优先收紧判定条件。

## 匹配依据

`file` + `category` + 归一化后的 `quote` 三元组。归一化做 NFKC 并折叠空白，
因此全角半角与空格差异不影响匹配；标点与措辞差异仍会影响匹配。

引文要抄得与模型一致：模型引用哪一段，金标就引用哪一段。同一处问题模型可能引「帐号」，
也可能引整句，两者匹配不上，会同时算成一次漏报与一次误报——这类噪声本身就是信号，
说明模型引文的口径还不稳。

## 计数口径

- **按原始条目数计，不去重。** 同一处问题被模型报了三次，就是三条预测：
  三条都进分母，多出的两条进误报清单。去重计数会让「重复报三遍」与「报一遍」
  得到同一个精确率——指标看不见这种退化，输出却写着 100%。
- **级别也参与判定。** 匹配键相同但 `severity` 不同的，算「级别不符」：
  问题找对了，定级错了。它不算干净命中，也不算漏报，单独列出来。
- **召回率与精确率算的是「找到」。** 干净命中与级别不符都算找到；
  干净命中的条数在输出里单列。

## 已知缺口

**确定性层（阶段①）目前没有任何被测量的召回率与误报率。** 这不是遗漏而是当前设计的取舍：
金标只收语义层九类，因为 `SKILL.md` 明确禁止模型写确定性层的类别，
把它们混进来会把「模型本来就不该报」永远算成漏报，指标直接失真。

这个范围是**写明且可验证**的：范围写在本文与 `gold_set.json` 的 `note` 字段里，
`tests/test_evaluate.py` 会解析 `references/content-rules.md` 的固定类别清单，
逐条校验金标里的类别确实属于语义层。要给确定性层做金标评估，得先决定
金标怎么同时容纳两层类别（或改成分两份金标分别评估），届时
上面那条校验测试也要跟着改——这一点在动手前别忘了。

## 样本量建议

起步 **10 至 15 份文档、约 100 条标注**，九类语义类别都要覆盖到。

样本量小于 30 条时，召回率的波动会很大，只用于发现明显缺口，不用于比较版本优劣。
要真正比较两个版本（改规则或改提示词），至少准备 50 条以上标注，并固定模型与提示词版本，
否则波动会盖过改动本身的效果。
