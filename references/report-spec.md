# HTML 报告结构规范

报告为单个 HTML 文件，CSS 内联，不引用任何 CDN、外部字体或 JavaScript 库。可离线打开、可邮件附件发送、可长期归档。附打印样式。

## 章节

| 章节 | 内容 |
|---|---|
| §0 检查范围与未能检查项 | 受检文件清单（类型、页数、字数、段落数、表格数、推断出的主体名、SHA256 前缀）；未能检查的文件与原因 |
| §1 结论概览 | 严重级分布条、类别分布、文件分布、重点提示（识别到的主体名称数、疑似混主体「文件级」处数、主体名误用「段落级」处数、待补充内容处数） |
| §2 硬伤速览 | 仅 P0 与 P1，一行一条：级别、文件、位置、问题 |
| §3 按文件明细 | 每文件一组，**语义层问题与确定性层的非样式类别**按类别分组，每条含级别徽章、类别、来源、置信度、位置、原文摘录、描述、建议；文件摘要含规模、结构（表数、行数、工作表数）与主体名。样式类问题（字体一致性、段落格式一致性）**不在这里逐条展开**，只给一句「另有 N 处样式问题，见 §4.2」 |
| §4 一致性差异 | 4.1 样式主流值（**按角色分组**，含角色与文件两列）；4.2 样式偏离明细（**按「文件 + 角色 + 项目 + 实际情况」聚合**，给出处数与位置列表）；4.3 体例差异；4.4 主体名分布与写法变体 |
| §5 待补充与待核实 | 待补充内容表；需人工核实项表。两表都是六列：勾选框、文件、位置、缺失内容/原文摘录、为何需要、建议。需人工核实项表两层都收 |
| §6 复查对比 | 仅在使用 --baseline 时出现。新增、已修复、未修复三表，外加文件改动提示 |
| §7 附录 | 本次检查档位与覆盖范围、检查规则与判定标准、文件 SHA256 |

**报告里的主体名取的是阶段①的「还原名」**（连接词裁剪把字号劈掉一半时更宽的那一段），不是裁剪后的残缺名。这份名单本身有已知缺口：整家公司被丢掉、两家公司被并成一个名字、还原名还原出的是一段句子碎片——三种情况都会让名单与原文对不上（边界见 format-rules.md「已知局限」）。**报告里没有某个主体名，不等于文档里没有这家公司**；报告里出现一个读起来像句子的名字，多半是句子碎片。人工复核一律以原文为准。

## 固定声明

每份报告必须包含能力边界声明（位于报告页脚，全文必含）：本工具仅做文档内互查，未核实外部事实。企业名称是否真实存在、引用文献是否真实存在、法规是否现行有效，均需人工核实。

## 按字面量筛选的两张表

§5 的两张表是按字面量筛的，不看语义：

- 待补充内容表只收 category 为「待补充内容」的条目。
- 需人工核实项表只收 confidence 为「疑似 · 需人工核实」的条目，两层都收：模型写的 findings，以及确定性层本身标为「疑似」的 P0 主体串写。

字面量写错的条目仍会出现在 §1、§2、§3（问题不会丢），但会从读者真正用来逐条过活的表里消失。
所以类别名与置信度必须照 references/content-rules.md、references/severity.md 里的写法抄，不要自造近义写法。

样式类问题（字体一致性、段落格式一致性）的正文不在 §3 逐条展开，而在 §4.2 聚合呈现。
它们的类别名仍按同一份固定清单校验——写错字面量会让 validate_findings 拦下整个 findings.json。

## 转义

所有来自文档与模型的文本必须 HTML 转义后再输出。
