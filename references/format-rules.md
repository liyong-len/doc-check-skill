# 格式与体例层规则（阶段①确定性检查产出，供核对与排查）

以下问题由脚本判定，置信度为「确定」，唯一的例外是 P0「主体串写」。本文件记录判定标准，供人工复核与规则调整时参考。
语义层不要重复报告这些类别（见 content-rules.md）。

## 字体一致性
中文字体、西文字体、字号与全文主流值不一致。主流值定义为出现次数最多的取值，且其占比不低于 60%，否则不报；参与统计的段落少于 3 个也不报。偏离段落逐条列出文件名、段序、实际值与主流值。段落样式取该段落首个非空 run 的属性；段落没有非空 run 时记为「未设置」，不继承段落样式。

## 段落格式一致性
对齐方式、左缩进、首行缩进、行距、段前距、段后距与主流值不一致。判定规则同字体一致性。

## 标题层级体例
同一层级内混用两种以上标题编号写法即报。体系清单：第一章式、一、式、1. 式、（一）式、1.1 式。
不同层级用不同写法是正常结构（第一章 / 一、 / 1. /（一）），不因此报体例不一致。
另检查标题层级跳级：上一级标题与本标题之间缺少中间层级（如 H1 直接跳 H3）即报。

## 图表题注体例
同一文件内同一类对象出现两种以上题注写法即报。**图与表各是一套独立的编号体系，写法只在同一类内部比较**——「图3-1 流程图」与「表3-1 清单」是正确写法，不是混用。
写法清单：图 N-N、图N-N、图 N.N、图N.N、图N，以及对应的表 N-N、表N-N、表 N.N、表N.N、表N。带章节号的写法里，数字前有没有空格算两种写法（规范里的例子就是「图1-1」与「图 1-1」）。
**不带章节号的写法只有一种**（「图N」）：正文里的交叉引用「设备如图 3 所示。」与题注「图3 流程图」会同时出现在一份文件里，把它们分成两种写法就报出一条确定级的假问题。
另检查编号缺号：只有「图N-N」「表N-N」形式参与缺号检查（「图N.N」「图N」不参与缺号检查）；**图与表按 (对象类型, 章) 分成两条序列各自查缺号**，第 3 章有「图3-1」与「表3-3」不报缺号。

## 表格体例
各表首行的加粗写法与全文主流写法不一致即报，主流写法占比不低于 60% 才报。
xlsx 的表头行取首行非空且下方存在数据的行。xlsx 的表格同样参与这项检查——单元格的字体与加粗信息会随单元格一起抽出来。

## 主体名称
同一主体出现两种以上名称写法。

**建议统一成哪一种写法，只有文档内有依据时才给**：只有一种写法是企业形式的全称时，建议统一成它（另一个写法是裸字号或组织形式词，不是另一个注册名称）。两种写法都是注册过的全称时（「…有限公司」与「…有限责任公司」），文档里没有任何依据能判断哪一个才是正式写法——那是企业登记信息，文档内无从查证——此时不挑，改成说明「文档中没有判断哪一种是正式全称的依据，需人工核实后确定」。凭空挑一个会让用户去统一两个注册名称。

**归组基准是规范核心字号**（`canonical_core`）：去掉公司词尾（可叠层，只剥企业形式词——研究院、研究所、设计院、事务所不是企业形式，不剥）、**保留行政区划前缀**、去掉开头的连接词。

**裁剪出来的名字可能是残缺的，聚类与报告用的是「还原名」**：连接词裁剪取的是**最短**的那个合格切分，裁剪点因此有时落在字号内部——`本项目由中国自由贸易港城有限公司` 里第二个「由」是「自由」的一半，字号被劈成 `贸易港城`。同一个前缀有不止一个合格切分时，抽取器按下面两条规则挑出**更宽的那一段**当还原名（`中国自由贸易港城有限公司`），报告里的主体清单、主体名分布表、写法变体表以及归组用的都是还原名。

**还原名的两条规则**（`scripts/entities.py` 的 `_trim_prefix_details` 与 `_connector_word_candidates`）：

- **条款 (a)：更宽的候选切在同一个连接词上。** 两个字号的两个切点落在同一个连接词上，说明那个连接词出现在字号内部（`本项目由中国自由贸易港城` 的两个「由」），更宽的那一段才是同一个字号的更宽视角。
- **条款 (b)：更宽的候选被裁掉的那一段，整个是一个完整的角色词。** 条款 (a) 是一个正确但很窄的特例：散文里的分隔词与字号内部的连接词**不是同一个词**时，它不适用，真字号会被劈掉一半。`中标人为北京自由空间科技有限公司` 里的分隔词是「中标人」，字号内部的连接词是「自由」里的「由」——两个词不是同一个，条款 (a) 救不回来，字号被劈成 `空间科技`。条款 (b) 认的是另一件事：**被裁掉的那一段是不是一个完整的角色词**（`中标人`、`实施单位`、`招标人`、`采购方`、`乙方`、`甲方`、`我方`、`贵方`、`供货商`、`承接方`、`受托方`…）。这一句散文里被裁掉的正是「中标人」——一个完整的角色词，说明裁剪点落在词边界上，剩下的是真字号，于是还原成 `北京自由空间科技有限公司`。

条款 (b) 有四道守卫，缺一不可：

1. 前缀**以**角色词开头，多一个字都不行。代码判的是 `prefix.startswith(word)`，而 `prefix` 是公司形式词之前的**整段**文字，连同前面的散文一起。`根据采购方要求由北京华信科技有限公司` 的前缀整段是「根据采购方」——带了填充词「根据」，不是一个角色词，条款 (b) 不成立；`本项目中标人为北京自由空间科技有限公司` 的前缀以「本项目」开头，同样不成立，那一句只剩 `空间科技有限公司`（见「已知局限」里「角色词前面带填充词时，两家不同的公司会静默合并」那一条）。
2. 那一刀没有把一个更长的角色词劈成两半。`受托方是北京华信科技有限公司` 在「受托」处切开，剩下 `方是北京华信科技`——「受托方」被劈开了，那一刀切在词中间，剩下的是另一段句子碎片，不是字号的更宽视角。
3. 角色词与误切点之间的那一段**以行政区划或国家前缀开头**。`乙方认可后由北京华信科技有限公司` 的角色词是「乙方」，误切点之前却夹着「认可后」，那是句子的成分，说明这一刀切早了，还原出来的是一段句子而不是字号。
   **这条守卫只检查「开头」，不检查这一段是不是字号本身的开头**：代码里的 `_is_wordmark_head` 只看这一段**是不是以某个行政区划或国家前缀开头**。因此 `乙方为北京分公司确认自由空间科技有限公司` 里的「北京分公司确认」照样通过（它以「北京」开头），还原出来的是 `北京分公司确认自由空间科技有限公司`——一段句子碎片被当成公司名发布（见「已知局限」里「条款 (b) 的第三条守卫只检查开头，会还原出句子碎片」那一条）。
4. 候选不是句子碎片（以连接词开头，或夹着句子级连接词）。

**角色词这张表与上面的连接词表不是一回事**，别混：连接词表（`_CONNECTORS`）管的是**裁剪**——表里的词在裁剪时可能被切掉；角色词表（`_COMPLETE_SENTENCE_CONNECTORS`）管的是**还原**——它回答的是「被裁掉的那一段整个是不是一个角色词」。`实施单位` 在角色词表里而**不在**连接词表里，因此它本身不会被裁掉（`实施单位是华信科技有限公司` 裁出来的是一整串句子碎片，见「已知局限」），但它可以成为条款 (b) 认出的那一段。

角色词后面可以跟一个系词，系词是句子的成分，不属于字号。**系词表只有两个：「是」「为」**（代码里的 `_COPULAS = ("是", "为")`）。「系」「即」也是常见的中文系词，恰好出现在这个机制针对的投标登记句式里，但**不在表内**：`中标人系北京自由空间科技有限公司`、`中标人即北京自由空间科技有限公司` 的角色词后面跟的不是「是」「为」，条款 (b) 不成立，两句都只剩 `空间科技有限公司`。

**角色词表里也收了「由」——它不是角色词，是连接词**（`_CONNECTORS` 里的句子级连接词）。它生效的场合很窄：条款 (b) 判的是 `prefix.startswith(word)`，只有当整段前缀**以「由」开头**时，「由」才被当成角色词；`本项目由北京自由空间科技有限公司` 这种写法不成立（`prefix` 以「本项目」开头）。绝大多数情况下这条路根本不进；少数写法里它会单独促成一个把两家公司连起来的还原名——`由北京和深圳华信科技有限公司` 还原成 `北京和深圳华信科技有限公司`，那不是公司名，报告里会多出一个主体并报出一条**疑似级**的 P0「主体串写」。把「由」从角色词表里删掉属于代码改动，不在本波范围内；这里只把它的存在与影响写清楚。

**第二条守卫（`_splits_a_connector_word`）只防一种切法**：更长的角色词以更短的为前缀（`受托` ⊂ `受托方`）。角色词表里成对的只有 `受托`→`受托方`/`受托人`、`委托`→`委托方`/`委托人`、`招标代理`→`招标代理方`；`甲方`/`乙方`/`我方`/`贵方` 没有更长的形式，不存在「被劈成两半」的情形，这道守卫对它们不适用。

两条规则都不成立时（裸字符串 `中国自由贸易港城有限公司` 只有一个合格切分），还原名与裁剪后的名字相同。

**还原名是文档里逐字存在的字符串，不等于它是一个公司名。** 逐字存在只说明它不是凭空造出来的；它照样可能是一段句子碎片。因此**不能**由「还原名不是凭空造出来的」推出「还原名不会报出确定级的 P1『主体名称』」——碎片与真字号能不能分开，靠的是归组时那条「多出来的那部分是不是句子碎片」的规则（见下面「主体名称」一节），它覆盖常见的碎片形态，覆盖不了全部写法。还原名解决的是「两家不同的公司被裁成同一个名字」——**在还原名规则成立时**它们分得开，不会被并成一家；规则不成立时它们仍会被并成一家（见「已知局限」里「散文里还原不出来的情况」那一条）。

**还原名的覆盖面：条款 (b) 只覆盖「角色词位于名字串开头」的散文写法。** 真实投标文档里更常见的写法恰恰是角色词前面带填充词——`本项目中标人为…`、`本次采购中标人为…`、`确定中标人为…`、`本项目中标单位为…`、`本项目中标为…`——或者角色词后面跟了别的系词——`中标人系…`、`中标人即…`、`兹确定…为中标人`。这些写法里角色词**不在名字串的开头**（或后面不是「是」「为」），条款 (b) 不成立，散文里那家公司只剩一个被裁过的残缺名。条款 (a) 覆盖的是另一类：分隔词与字号内部的连接词**是同一个词**（`本项目由中国自由贸易港城有限公司` 的两个切点都切在「由」上），它对角色词这一类无能为力。**两条规则加起来，仍有相当一部分真实写法还原不出来**——这一类是漏报，不是误报，但它比「报一条疑似」隐蔽得多，见「已知局限」。

**去掉连接词的规则**（`_connector_cut_allowed`）与抽取时**完全一致**，连接词也只有一张表（`_CONNECTORS`），分「句子级」与「字号级」两类：

- **句子级**连接词：以及、并且、我方、贵司、双方、各方、甲方、乙方、中标人、投标人、供应商、承包人、采购方、招标人、招标代理、受托、委托、由
- **字号级**连接词：联合、协作、为、和、同、经、并、及、与、是、从、给、向、对、或、代理

判定顺序（与代码里 `_connector_cut_allowed` 的判断顺序一一对应）：

1. 连接词后面剩下的部分**不到 4 个字**（`_MIN_PREFIX_LEN = 4`）→ **不裁**：太短说明连接词本身就是字号的一部分（「华为技术」中的「为」、「为信科技」）
2. 连接词后面紧跟**行政区划** → **裁**：其后几乎必然是新主体（「联合北京华信科技」「和深圳华信科技」）
3. **字号级**连接词 → **不裁**（除非它后面紧跟行政区划）：字号级连接词后面不是行政区划时，它是字号的一部分（「和而泰智能控制」「中国联合网络通信集团」「清华同方科技」）
4. **句子级**连接词，且它前面那段文字是**空的** → **裁**
5. **句子级**连接词，且它前面那段文字以**行政区划**开头 → **不裁**：「海南自由贸易港城有限公司」是一个完整的字号，里面的「由」是字号的一部分。注意**必须是前缀部分的开头**：裸字符串 `海南自由贸易港城有限公司` 的头部是「海南自」，规则生效；**放进句子里就不成立**——`本项目由海南自由贸易港城有限公司中标。` 的头部是「本项目由海南自」，行政区划在中间，规则不生效，照样被裁成「贸易港城有限公司」
6. **句子级**连接词，且它前面那段文字以**国家前缀**（「中国」「中华」）开头**并且本身以完整的企业/组织形式词结尾** → **不裁**。完整形式词指 `集团`、`有限公司`、`有限责任公司`、`股份有限公司`、`研究院`、`研究所`、`设计院`、`事务所`；光秃秃的「公司」「有限」「股份」**不算**——以它们结尾的头部（「中国石油有限」）不是完整字号，拿它挡住裁剪会抽出一个并不存在的公司名（`中国石油有限由华为技术有限公司`）。头部只是「以国家前缀开头的开放从句」（如「中国联通本次项目」）时**照裁**：从句不是字号，裁掉之后后面那家公司才抽得出来——`中国联通本次项目由华为技术有限公司` → `华为技术有限公司`。
   **这条守卫的实际覆盖面比看上去小得多**：头部是「连接词前面那一段」，而抽取用的前缀部分止于**第一个形式词之前**，所以普通散文里的头部里根本不出现完整的形式词——`中国联通集团由华为技术有限公司中标。` 的头部是「中国联通」（「集团」在形式词那一侧），**到不了这条规则**。「中国联通集团」这样的完整字号**不会**触发它。它实际保护的是**形式词被拆进括号里**的写法：头部成了「中国(集团」，以形式词结尾，守卫因此生效，连接词不被裁掉；没有它，`中国(集团由华为技术)有限公司` 会被裁成 `华为技术)有限公司`——一个括号都不配平的错名字。
   结论：**这条守卫不会在普通字号散文上生效**，以国家前缀开头的开放从句一律照裁；`中国自由贸易港城有限公司` 仍被裁成 `贸易港城有限公司`（头部「中国自」是开放从句），这是记录在案的已知局限。
7. 其余情况：连接词前面那段文字**至少两个字** → **裁**（句子碎片，「本文件由华为技术有限公司」「由甲方及乙方共同委托北京华信科技有限公司」）；**只有一个字** → **不裁**，那个字与连接词同属字号（「自由贸易港城」里的「由」）

**国家前缀单列一张表**（代码里的 `_COUNTRY_PREFIXES` = 中国、中华），**不放在行政区划表里**：「中国」不是行政区划，放进去会让「中国建筑」被当成「以行政区划开头的简称」，`中国建筑` 与 `中国建筑科技` 就成了一家。国家前缀在两处检查，两处问的问题**不一样**，别混：

- 连接词前面那段（上面第 6 条）问的是「这一段**本身是不是一个完整字号**」——是完整字号才挡裁剪；
- 归组时多出来的那部分（下面「同一主体」的判定）问的是「这一段是不是**区分标志**」——不看是不是完整字号：`中国联合网络通信集团有限公司` 与 `联合网络通信有限公司` 是集团公司与子公司，多出来的「中国」本身就是区分标志。

两个名称是同一主体，当且仅当满足其一：

- 规范核心字号完全相同
- 互为**后缀**，且多出来的那部分**不含字号级连接词**、**也不是行政区划**、**也不是国家前缀**、**也不是以行业词结尾**（「由北京华信科技」与「北京华信科技」是同一主体；「联合网络通信」与「网络通信」不是；「上海华为技术有限公司」与「华为技术有限公司」是两家不同的公司，行政区划是区分标志，不是语气词；「中国联合网络通信集团有限公司」与「联合网络通信有限公司」也是两家不同的公司——集团公司与子公司，国家前缀同样是区分标志；多出来的那部分以行业词（`技术`、`服务`、`咨询`…）结尾时同样不合并——那描述的是经营范围，不是字号本身）
  **两个都是全称时还要多一条**：多出来的那部分必须**看起来是一段句子碎片**（含句子级连接词，如「甲方」「委托」；或以「的」结尾，如「甲方**指定的**」）。**「由」不算碎片的标记**——它常出现在字号中间（「自由」），拿它当标记会把 `北方自由` 这种专有名词误判成碎片。多出来的是一段**专有名词**（`北方自由`）时，文档里没有任何依据说它是同一家公司的写法差异——它很可能是另一家公司：`北方自由贸易港城有限公司` 与 `贸易港城有限公司` 是两家不同的公司，后者的字号被裁掉了一半（作为裸字符串出现时还原不回来，见「已知局限」）。这种情形**不合并**，只报疑似级的 P0「主体串写」；合并会报出确定级的 P1「主体名称」，建议是「全套文档统一使用同一名称；文档中没有判断哪一种是正式全称的依据，需人工核实后确定」——那是确定级的假阳性。
  **这条规则管的是归组，不管还原名。** 两者都用「多出来的那部分是不是句子碎片」这一类判断，但问的问题不同：归组问「这两个写法是不是同一家公司」，还原名问「这一段更宽的文字是不是同一个字号的更宽视角」。还原名有它自己的两条规则（见上面「主体名称」一节）。**早先版本的还原名只认「切在同一个连接词上」的那一个更宽候选**，因此散文里的分隔词与字号内部的连接词不是同一个词时（`中标人为北京自由空间科技有限公司`：分隔词是「中标人」，字号内部的连接词是「自由」里的「由」），真正的字号会被劈掉一半，只剩 `空间科技有限公司`；而这一条在规则文档里看不出来——文档只写了「由」的排除对归组的影响，读者会以为它与还原名无关。
- 互为**前缀**，且较短一方是**裸字号**（没有公司形式词的写法，如「北京华信」），并且它**像简称**：不超过 3 个字，或以行政区划开头，**且不以行业词结尾**（「北京华信」是「北京华信科技有限公司」的简称；「北京华信科技」不是「北京华信科技服务有限公司」的简称，那是两家不同的公司）

**前缀关系只对裸字号成立**：两个**全称**的核心字号一短一长，是两家公司。「北京华信集团有限公司」剥掉「集团」之后的核心字号是「北京华信」，与简称同形，但它与「北京华信科技有限公司」不是一家——集团是母公司的形式词。

**裸字号只有在不歧义时才是简称**：「北京华信」在「北京华信集团有限公司」与「北京华信科技有限公司」同时出现时，指的是哪一家，文档本身没有依据。它单独成组，不并进任何一家，也不产生「写法不统一」的结论。

**保留行政区划是关键**：「北京华信科技」与「上海华信科技」是两家不同的公司，绝不能归并。行业词同样不剥离，「华信科技」与「华信信息技术」是两个不同主体。（归组基准是 `canonical_core`，它保留行政区划；`core_key` 那个「剥掉行政区划」的口径**只为测试保留**，流水线不调用它，报告里也不出现它。）

聚类结果与名字出现的顺序无关：先按规范核心字号精确分组，再按显式的规则跨组合并——两组之间每一对名字都互为同一主体时才合并。同样的一批名字换个顺序，分组不变。

## 主体名的发现规则
哪些名称会被抽出来，取决于：

- **公司形式词**：股份有限公司、有限责任公司、集团有限公司、有限公司、集团、研究院、研究所、设计院、事务所。「中心」不是企业形式——投标文档里「技术中心」「研发中心」随处可见，当成企业名会凭空造出第二个主体
- **连接词只有一张表**（`_CONNECTORS`），分两类：**句子级**（以及、并且、我方、贵司、双方、各方、甲方、乙方、中标人、投标人、供应商、承包人、采购方、招标人、招标代理、受托、委托、由）与**字号级**（联合、协作、为、和、同、经、并、及、与、是、从、给、向、对、或、代理）。裁不裁由**位置**决定，不由字本身决定，规则见上面「主体名称」一节
- **裁完至少要剩下 4 个字**（`_MIN_PREFIX_LEN = 4`）才裁。太短说明连接词本身就是字号的一部分，保留原样：「由甲公司」不会被裁成「甲公司」，「华为技术」里的「为」也不会被裁掉
- **括号**：括号整体被当作字号的一部分（`北京华信(集团)有限公司` 是一个字号）；但开头的注解括号不是（`（招标人）北京华信科技有限公司` 的字号是「北京华信科技有限公司」），注解括号里的内容也不单独成为主体（`（华信集团）北京华信科技有限公司` 只有一个主体）
- **名字延伸到最外层的形式词**：`北京华信集团研究院有限公司`、`中铁建工集团北京工程有限公司`、`华夏集团工程咨询有限公司` 各是一个名字，不会被切成两半。延伸过去的那截文字不再重新匹配一次
- **延伸遇到下一个主体就停**：中间那段文字里出现连接词时，名字停在第一个形式词处，下一个名字从**连接词本身**开始（不是从连接词之后），连接词要不要算进下一个名字由上面那条统一规则判断。判定**由连接词驱动，不只看行政区划**：`北京华信科技有限公司和华为技术有限公司` 是两个公司，不能并成一个叫「北京华信科技有限公司和华为技术有限公司」的名字。连接词出现在这段中间文字里是边界；连接词出现在**名字开头**时是字号的一部分（`和而泰智能控制股份有限公司`、`中国联合网络通信集团有限公司`、`清华同方科技股份有限公司` 各是一个名字），两者靠位置区分，不靠字本身。**字号级连接词出现在中间文字的开头**是边界（`…有限公司**和**华为技术有限公司`）；**字号级连接词出现在中间文字的中间**不是边界（`北京华信集团工程**与**设备有限公司` 是一个名字）。**句子级连接词出现在中间文字的中间**也不是边界（`中国石油集团**自由贸易**有限公司` 是一个名字）
- **通用片段不是名字**：两种情形——**字号整个就是形式词、没有任何自己的字**（`研究院有限公司`、`设计院有限公司`）；**没有行政区划前缀、且字号里全是行业词**（`工程咨询有限公司`）。字号是行业词本身不是拒绝理由：`北京工程咨询有限公司`、`北京科技发展有限公司`、`北京贸易有限公司`、`北京投资有限公司`、`北京信息技术有限公司`、`北京网络科技有限公司`、`北京建设工程有限公司`、`北京建设集团有限公司` 都是注册过的普通公司名，要抽出来。丢掉它们，文档看起来就只有一个主体，混主体的检查也跟着失效了。**这条判定用的是裁剪后的名字，不是还原名**——它与「字号被裁掉一半」叠在一起时会把**整家公司**从报告里丢掉，见「已知局限」里「通用片段判定用的是裁剪后的名字，整家公司可能被丢掉」那一条
- **行政区划**：名单在 `scripts/data/regions.txt`（随技能一起安装），收录省级行政区、**全部地级市**、自治州、盟与地区、计划单列市。简称规则、通用片段规则与连接词裁剪规则对城市一视同仁，不能只认直辖市：深圳、广州、厦门、大连、青岛、宁波、苏州、无锡、常州、南通、温州、嘉兴、绍兴、泉州、福州、合肥、南昌、济南、郑州、武汉、长沙、成都、贵阳、南宁、昆明、西安、兰州、银川、呼和浩特、东莞、佛山、中山、珠海、梅州、沈阳、长春、哈尔滨等都在列。**少一个城市就会有一条规则失效**：`中标人：和广州华信科技有限公司`里的「和」只有在其后是行政区划时才会被裁掉，广州不在名单里就裁不掉，会抽出一个并不存在的「和广州华信科技有限公司」。**名单里没有「中国」**——它不是行政区划，是国家名，单独一张表（`_COUNTRY_PREFIXES`），见上面「主体名称」一节

## 主体串写
同一文件内出现两个及以上不同主体名称即报。因无外部依据，置信度为「疑似 · 需人工核实」，不升级为确定。
文件名或章节标题中的主体名**按组判定**：文件名提到甲公司，只说明甲公司被显式区分了，文件里的乙公司仍然没有任何依据，仍要报（报出来的条目里只列未被区分的那些主体）。只有文件名与章节标题把文件里出现的每一个主体都点明了，才不报。
**按这一组的实际写法匹配，不能拿去掉行政区划的核心字号去匹配**：文件名「北京华信科技有限公司投标文件.docx」里含有「华信科技」，用核心字号去匹配，文件里的「上海华信科技有限公司」也会被当成「文件名已经点明了」，混主体就漏掉了。

## 数字与单位
同一文件内货币单位（元、万元）混用报 P1。日期格式（2024年1月1日、2024-01-01、2024/01/01、2024.01.01）混用报 P2。

## 引用标记
同一文件内引用标记写法混用即报。参与混用判定的写法：文献[n]、[n]、（n）。
**「（n）」要求前面有引用引导词**（参考文献、文献、参见、引自、依据、如表）才算引用标记写法。中文文档里「（1）」「（2）」通常是枚举序号，不是引用；没有引导词时不参与判定，否则每份带编号列表的文档都会误报。
单字引导词「见」「据」还要求落在**词边界**上：它们也是普通词的一部分，「意见（2）」「详见（3）」「数据（1）」「根据（2）」里的括号是枚举序号，不是引用标记。中文没有词边界可依，脚本用「常见的以它结尾的词」（意见、见解、常见、详见、数据、根据、依据、证据、票据、据说等）来挡。
引用编号是否越界、参考文献表是否缺项，脚本不判定，语义层也没有对应类别——这两项需要人工核对。

## 列表与编号
有序列表编号方式混用即报。

## 术语与缩写
缩写首次出现时未给出全称。脚本直接判定并产出 P3、置信度为「确定」的 finding，语义层不重复报这一类。缩写停用表共二十项：PDF、ISO、XML、HTML、URL、API、KPI、ROI、TBD、CPU、RAM、SSD、LED、CAD、CAM、PLC、TCP、UDP、HTTP、HTTPS。
表格单元格也参与检查：术语表（缩略语对照表）常在表格里，只看段落会把正文的缩写误报成「未给出全称」。

## 表格里的文字
主体名与缩写的发现**会看表格单元格**，与模型层（分片时读表格文字）的口径一致：一份只在表格里写出协作方的文档，确定性层也要能发现它。

## 置信度标注
pdf 抽取的样式数据置信度为低，不参与一致性统计，相关结论不产出。md 与 txt 无样式概念，脚本直接跳过样式相关检查，不产出 finding，也不产出「不适用」标记——报告里看不到这些检查项，是因为它们没有被执行。

## 已知局限
本节是抽取环节的真实边界，人工复核时不要把这些当成「文档里确实没有」：

- **嵌套括号、形式词被括号拆开，会整条漏掉**：`北京（华信（集团））科技有限公司`、`北京华信科技有限(公司)` 这样的写法都匹配不到公司形式词，于是名字根本不会被抽出来。这是漏报（假阴性），不是凭空造名。
- **两个公司之间的连接词与字号开头的连接词分不开**：`北京华信科技有限公司和华为技术有限公司`里的「和」与`北京华信科技有限公司和而泰智能控制股份有限公司`里的「和」在结构上完全一样——都在第一个形式词之后、第二个主体名之前。脚本按同一条规则处理：**连接词后面紧跟行政区划才裁掉**。因此「和深圳华信科技有限公司」会裁掉「和」（得到「深圳华信科技有限公司」），「和华为技术有限公司」与「和而泰智能控制股份有限公司」都保留「和」。同一个名字单独出现与跟在另一家公司后面时，读法一致。
- **字号过长匹配不到完整名称**：公司形式词之前的那一段超过 30 个字符时，正则最多只能容纳 30 个字符，匹配会整体后移，抽出来的是一个**缺了开头字**的错名字（实测 30 个字仍能完整匹配，31 个字起丢开头的字）。丢字不会导致整条抽不到——名字始终会被抽出来，只是前面少几个字；整条抽不到只发生在括号被拆开的写法上。
- **缩写停用表有二十项**：PDF、ISO、XML、HTML、URL、API、KPI、ROI、TBD、CPU、RAM、SSD、LED、CAD、CAM、PLC、TCP、UDP、HTTP、HTTPS。停用表里的缩写即使没给全称也不会报。
- **国家前缀这条规则只保护带括号的头部，普通散文一律照裁**：这条规则要求「连接词前面那一段」以国家前缀开头**并且以完整形式词结尾**。但抽取用的前缀部分止于**第一个形式词之前**，所以普通散文里的头部里根本不出现完整的形式词——`中国联通集团由华为技术有限公司中标。` 的头部是「中国联通」（「集团」在形式词那一侧），**到不了这条规则**；`中国联通集团` 这样的写法**不会**触发它。它实际保护的是形式词被拆进括号里的写法（头部成了「中国(集团」）：`中国(集团由华为技术)有限公司` 里的连接词因此不被裁掉；没有它，那一串会被裁成 `华为技术)有限公司`——一个括号都不配平的错名字。
  连带的后果是**字号被裁掉一半**：`中国自由贸易港城有限公司` 里的「由」是「自由」的一半，裁剪把它当成了句子级连接词，`中国自由贸易港城` 被劈成 `贸易港城`。开放从句一律照裁（`中国联通本次项目由华为技术有限公司` → `华为技术有限公司`）；反过来，早先那一版「头部只要以国家前缀开头就不裁」会把从句连同它后面那家公司一起吞进来，真正的 `华为技术有限公司` 反而整条丢掉；两家不同的公司还会被并成一家，报出确定级的 P1「主体名称」建议——那是更坏的一种错。
  **补救办法是「还原名」**：裁剪点落在字号内部时（同一个前缀有不止一个合格切分），抽取器按「还原名的两条规则」（见上面「主体名称」一节）挑出更宽的那一段还回来，报告与聚类用的是还原名而不是裁剪后的残缺名。**但还原名不是万能的：两条规则都要成立才还原得回来。** 散文里用「由」引出公司时走的是条款 (a)（`本项目由中国自由贸易港城有限公司中标` 的两个切点都切在「由」上），两家不同的公司因此分得开（`中国自由贸易港城有限公司` 与 `北方自由贸易港城有限公司`），不会被并成一家；散文里用角色词引出公司时走的是条款 (b)，而条款 (b) 要求角色词与误切点之间的那一段**以行政区划或国家前缀开头**。`中标人为北方自由贸易港城有限公司` 的中间是「北方自」，不是行政区划，条款 (b) 不成立，那一句还原不出来，只剩 `贸易港城有限公司`。**这时两家不同的公司会被并成一家，而且一条 finding 都不报**（见下面「散文里还原不出来的情况」）。规则成立、但还原名与别处的写法对不上时的结论，见下面「散文写法与裸字符串写法对不上时会误报疑似」那一条。
  **还原名本身不保证是一个公司名**：它是文档里逐字存在的一段文字，可能是字号，也可能是句子碎片。因此**不能**由「还原名不会造出假名」推出「还原名不会报出确定级的 P1『主体名称』」——碎片与真字号能不能分开，靠的是归组时那条「多出来的那部分是不是句子碎片」的规则，它覆盖常见的碎片形态（连接词、相对从句的「的」），覆盖不了全部写法。剩下的残余污染见下面「还原名仍可能是句子碎片」那一条。
  **还原不出来的情况是裸字符串**：`中国自由贸易港城有限公司` 单独出现时只有一个合格切分，还原不出来，只能用 `贸易港城有限公司`。此时它与散文里还原出来的 `北方自由贸易港城有限公司` **分成两组**：多出来的那部分（`北方自由`）是一段专有名词，文档里没有依据说它是同一家公司的写法差异，因此报出 P0「主体串写」，置信度是「疑似 · 需人工核实」，**不报**确定级的 P1「主体名称」。抽出来的 `贸易港城有限公司` 是文档里逐字存在的字符串，**没有凭空造名**——但它也不是一个公司名，它是裁剪剩下的残缺名，人工核对时要按残缺名对待。
  **散文写法与裸字符串写法对不上时会误报疑似**：同一家公司 `中国自由贸易港城有限公司`，散文里还原成 `中国自由贸易港城有限公司`，裸字符串却只能用 `贸易港城有限公司`；两者的字号一长一短、差的是国家前缀「中国」（区分标志），因此分成两组，报出疑似级的 P0「主体串写」。这是**误报（假阳性）**，但只在疑似级——把它并成一家会报出确定级的 P1「主体名称」建议，性质更坏。
  行政区划那条规则的覆盖面更窄：它只在**行政区划是前缀部分的开头**时生效。裸字符串 `海南自由贸易港城有限公司` 完整保留（头部是「海南自」）；**放进句子里就不成立**——`本项目由海南自由贸易港城有限公司中标。` 的头部是「本项目由海南自」，行政区划在中间，那条规则不生效，同样被裁成 `贸易港城有限公司`（还原名仍能把它还原成 `海南自由贸易港城有限公司`，但那是还原的结果，不是行政区划那条规则起了作用）。
- **通用片段判定用的是裁剪后的名字，整家公司可能被丢掉**：`_generic_fragment` 判的是**裁剪后**的那一段，不是还原名。`本项目中标为青岛自由贸易服务有限公司。` 裁出来的是 `贸易服务有限公司`——没有行政区划前缀、且全是行业词，于是被判为通用片段，这条出现**在还原名被考虑之前**就被丢弃；还原名 `青岛自由贸易服务有限公司` 即使算对了也扔掉。同族的写法（`深圳自由科技发展有限公司`、`北京自由网络建设发展有限公司`、`杭州自由信息工程咨询有限公司`）同理：**报告里一条名字都不发布**。
  这是上面「字号被裁掉一半」与「主体名的发现规则」里「通用片段不是名字」两条**交互**出来的结果：单看「字号被裁掉一半」，残缺名还在报告里；单看「通用片段不是名字」，丢的只是一个通用片段；两条叠在一起，**整家公司从报告里消失**。这是漏报（假阴性），且是既有的，不是最近这一波引入的。
  **不对称**：同一家公司在**裸字符串**里出现时是对的（联系方式块、落款、投标人表里的 `青岛自由贸易服务有限公司` 单独出现就被抽出来）。所以**报告里的主体清单取决于哪一句引入了这家公司**——同一家公司在文件里换个位置出现，可能就查不到了。**不能以「报告里没有这家主体」推断「文档里没有这家公司」**，人工复核时必须回原文确认。
- **还原名仍可能是句子碎片**：还原名是文档里逐字存在的一段文字，**不是**凭空造出来的名字，但**也不保证是一个公司名**——它照样可能是一段没裁干净的句子碎片。这一版的还原名有两条规则（见上面「主体名称」一节）：条款 (a) 只认切在同一个连接词上的那一段，条款 (b) 只认被裁掉的那一段**整个是一个完整角色词**的那一段。常见的两种污染因此被挡住了：`受托方是北京华信科技有限公司` 不会被还原成 `方是北京华信科技有限公司`（条款 (b) 的碎片检查：那一刀把角色词「受托方」劈开了），`根据采购方要求由北京华信科技有限公司负责实施` 不会被还原成 `要求由北京华信科技有限公司`（条款 (b) 的第一条守卫：前缀整段是「根据采购方」，带了填充词「根据」，不是一个角色词）。但裁剪只做一遍（见下面「为」那一条），句子碎片留在名字里的情形仍然存在：`甲方指定的北京华信科技有限公司` 裁出来的是 `指定的北京华信科技有限公司`。**这类名字不是公司名**，人工核对时要按碎片对待。碎片与真字号能不能分开，靠的是归组时那条「多出来的那部分是不是句子碎片」的规则（覆盖常见的碎片形态）；**覆盖不了的残余情形有两种后果**：要么并进同一组、报出确定级的 P1「主体名称」（建议里会出现那个碎片），要么分成两组、报出疑似级的 P0「主体串写」。两种都是把碎片当成了名字，**不要**把确定级那条当成「文档里真的有两种写法」。
- **条款 (b) 的第三条守卫只检查开头，会还原出句子碎片**：`_is_wordmark_head` 只看角色词与误切点之间那一段**是不是以行政区划或国家前缀开头**，不检查它是不是字号本身的开头。因此 `乙方为北京分公司确认自由空间科技有限公司。` 还原成 `北京分公司确认自由空间科技有限公司`，`中标人为北京负责人与北京华信集团` 还原成 `北京负责人与北京华信集团`——都不是公司名。
  这些碎片**一般不会与其他公司归并**（多出来的那部分以行政区划开头时，归组规则会挡住），因此不产生确定级的断言，只产生**疑似级**的 P0「主体串写」，不违反任何硬规则；但报告里会出现读起来很荒唐的名字。**人工核对时按碎片对待**——与上面「还原名仍可能是句子碎片」是同一族，只是这一族的入口是条款 (b) 的第三条守卫。
- **角色词本身不是连接词，裁不掉**：`实施单位` 不在连接词表里（连接词表见上面「主体名称」一节），所以它本身不会被裁掉；而紧跟其后的「是」是**字号级**连接词，后面不接行政区划时按规则不裁（见上面「主体名称」一节第 3 条）。于是 `实施单位是华信科技有限公司` 裁出来的是 `实施单位是华信科技有限公司` 这一整串句子碎片。冠名带行政区划时不暴露（`实施单位是北京华信科技有限公司` 的「是」后面紧跟行政区划，照裁）；**冠名不带行政区划时暴露**。这与下面「句子级连接词后面又跟一个「为」」是同一族：角色词被裁掉之后，剩下的那一截没有再裁一遍（链式裁剪本版未实现）。**它不会产生确定级的断言**（只到疑似级的 P0「主体串写」），但报告里会出现一个读起来很荒唐的名字。
- **散文里还原不出来的情况**：还原名有两条规则（见上面「主体名称」一节），两条都不成立时，散文里那家公司就只剩一个残缺名。条款 (a)（更宽的候选切在同一个连接词上）要求散文里的分隔词与字号内部的连接词**是同一个词**：用「由」引出公司时成立（`本项目由中国自由贸易港城有限公司中标` → `中国自由贸易港城有限公司`）；用角色词引出公司时不成立（`中标人为北京自由空间科技有限公司` 里，分隔词是「中标人」，字号内部的连接词是「自由」里的「由」，两个词不是同一个）。条款 (b)（被裁掉的那一段整个是一个完整的角色词）补上了角色词这一类，但要求角色词与误切点之间的那一段**以行政区划或国家前缀开头**。字号含「由」的公司（`自由`、`理由`、`由于`）常常满足这一条（`中标人为北京自由空间科技有限公司` → `北京自由空间科技有限公司`），冠名不是行政区划时却不满足（`中标人为北方自由贸易港城有限公司` → 中间是「北方自」，条款 (b) 不成立）。**注意这一条的触发点不是「冠名是不是行政区划」，而是「角色词是不是名字串的开头」**——`本项目中标为北京自由空间科技有限公司` 的冠名是行政区划，条款 (b) 却不成立（`prefix` 以「本项目」开头），见上面「还原名的覆盖面」一节。
  **后果是两家不同的公司会被并成一家，而且一条 finding 都不报**：`中标人为北方自由贸易港城有限公司` 与 `中标人为南方自由贸易港城有限公司` 都还原不出来，都只剩 `贸易港城有限公司`，归组时是同一个主体，混主体的检查因此**失效**——文档里写混了两家公司，工具一声不吭。这是漏报（假阴性）：比确定级的假阳性轻，但比「报一条疑似」隐蔽得多。**人工复核时按残缺名对待**——凡是名字短得像是被裁掉一半的（冠名不见了、字号的头几个字不见了），都要回原文里找全称。冠名是行政区划时（`北京…`、`上海…`）两家不同的公司**在角色词位于名字串开头时**分得开，报的是疑似级的 P0「主体串写」，不会静默合并；**角色词前面带填充词时不成立**（`本项目中标为北京自由空间科技有限公司` 与 `本项目中标为上海自由空间科技有限公司` 照样静默合并），见下面「角色词前面带填充词时，两家不同的公司会静默合并」那一条。
- **角色词前面带填充词时，两家不同的公司会被并成一家，而且一条 finding 都不报**：条款 (b) 要求角色词是整段前缀的**开头**（代码判的是 `prefix.startswith(word)`）。`本项目中标为北京自由空间科技有限公司。` 与 `本项目中标为上海自由空间科技有限公司。` 的前缀整段是「本项目中标为」，以「本」开头，不是角色词，条款 (b) 不成立，两句都只剩 `空间科技有限公司`，归组时是同一个主体，混主体的检查因此**失效**——文档里写混了两家公司，工具一声不吭。
  同族的写法还有 `本次采购中标人为…`、`确定中标人为…`、`本项目中标单位为…`、`中标人系…`、`中标人即…`、`兹确定…为中标人`（`中标人系…` 与 `中标人即…` 还叠加了系词不是「是」「为」的问题）。**冠名是不是行政区划与此无关**：`北京…`/`上海…` 只在角色词位于名字串开头时（`中标人为北京自由空间科技有限公司`）才分得开，报的是疑似级的 P0「主体串写」；`本项目中标为北京…` 与 `本项目中标为上海…` 照样静默合并。非行政区划冠名的写法（`中标人为北方自由贸易港城有限公司` 与 `中标人为南方自由贸易港城有限公司`）在角色词位于开头时也静默合并。
  **这是漏报（假阴性）**：比确定级的假阳性轻，但比「报一条疑似」隐蔽得多。**人工复核时必须回原文确认主体归属**——报告里只列得出一个主体名，看不出原文里写的是两家公司；凡是名字短得像是被裁掉一半的（冠名不见了、字号的头几个字不见了），都要回原文里找全称。
- **字号相同、只差企业形式词，会被当成同一个主体**：`中国建筑集团有限公司` 与 `中国建筑股份有限公司`、`中国石油集团有限公司` 与 `中国石油股份有限公司` 归组时是同一个主体（核心字号分别是「中国建筑」「中国石油」），工具报的是 **P1「主体名称」（确定）**，建议「全套文档统一使用同一名称」。**这条建议可能是错的**：按登记实践，`有限公司` 与 `有限责任公司`、集团公司与股份公司是**不同的企业形式**，可能是两家分别注册的独立公司（「中国建筑集团」与「中国建筑股份」就是两家各自上市的主体）。文档内部没有任何依据能分辨「同一家公司的两种写法」与「两家共享字号的独立公司」，只能由人工核对企业登记信息。上面「主体名称」一节已经就这一类把建议改成了「文档中没有判断哪一种是正式全称的依据，需人工核实后确定」，但那说的是**挑哪一种写法**，不是**它们是不是一家**。这是已知的取舍：核心字号相同即同一主体是本工具既定的口径（spec §5.4「主体名自动发现」、`severity.md`「置信度」一节），改了它，跨文件的「写法不统一」检查就整个失效了——那是这个工具最有用的一项。
- **前缀白名单只有两张单子，头部是别的专有名词时挡不住**：行政区划表只有省、市、州、盟、地区，没有「中国」——「中国」是国家名不是行政区划，放进去会让「中国建筑」被当成「以行政区划开头的简称」，`中国建筑` 与 `中国建筑科技` 就成了一家。因此另设 `_COUNTRY_PREFIXES`（中国、中华），在**连接词前面那段**与**归组时多出来的那部分**两处检查（两处问的问题不一样，见上面「主体名称」一节）。**残余代价**：判断「头部是不是区分标志」仍然只认这两张单子，头部是别的专有名词时，句子级连接词照样会被裁掉——`北方自由贸易港城有限公司` 被裁成 `贸易港城有限公司`，`华夏自由贸易港城有限公司` 同样。这与把带「中国」前缀的公司并进对方那条是**同一个根因**：前缀白名单不全，要么把一个完整的字号劈成两半，要么把两家不同的公司并成一家。**「并成一家」这一条现在由归组规则挡着**：多出来的那部分是一段专有名词时不再合并，因此 `北方自由贸易港城有限公司` 与 `贸易港城有限公司` 分成两组，报疑似级的 P0「主体串写」，而不是确定级的 P1「主体名称」（见上面「主体名称」一节）。**「劈成两半」这一条挡不住**：字号被劈掉的那一半还原不回来时（裸字符串），只能用那个残缺名。
- **句子级连接词后面又跟一个「为」，抽出来的名字带一个「为」**：`中标人为华为技术有限公司` 抽出的是 `为华为技术有限公司`，`甲方为北方国际股份有限公司` 抽出的是 `为北方国际股份有限公司`。触发条件是**句子级连接词**（中标人、甲方、乙方、投标人、供应商…）被裁掉之后，紧接着的**字号级**连接词「为」不再被裁——字号级连接词后面不是行政区划时按规则就不裁（见上面「主体名称」一节第 3 条），而裁剪**只做一遍**，不对裁剩的部分再裁一次。另一种表现是「为」后面剩下的字不足 4 个时，句子级连接词也不裁（`_MIN_PREFIX_LEN = 4`），抽出来的是完整的一串 `供应商为长江有限责任公司`。抽出来的字符串是文档里逐字存在的，**没有凭空造名**，也**不会产生确定级断言**（它只到 P0「主体串写」这一层，置信度是「疑似 · 需人工核实」），但读起来很荒唐。投标文档里「中标人为XX公司」「业主为XX公司」到处都是，这一类会经常出现。已知的修法是**链式裁剪**（句子级连接词被裁掉之后，对剩下的开头再按「同一句里的连接词」裁一次），**本版未实现**。
